# POC #5 — Signal Declaration + Go ↔ GDScript Round-Trip

**Status:** PASS (with one upstream API gap to paper over in gogogd)
**Date:** 2026-05-21
**Graphics.GD version:** `v0.0.0-20260521203745-bcb92de10087`
**Godot version:** `4.6.2.stable.official.71f334935`

## Hypothesis

ARCHITECTURE.md verified fact #8 + §10:
- `Signal.Void / Signal.Solo[T] / Signal.Pair[A,B] / ...` declared as exported struct fields are first-class GDScript signals.
- Field name converts to snake_case (matching POC #3's method behavior).
- Go can `Emit` and connect Go handlers; GDScript can `signal.connect(...)` and receive emissions; both fire on a single `Emit`.

## Test setup

```go
type Probe struct {
    Node.Extension[Probe]
    Ping    Signal.Void
    Damaged Signal.Solo[int]
    Moved   Signal.Pair[string, Vector2.XY]
}
```

- Go connects local handlers in `Ready()`.
- GDScript `Listener` (sibling node) connects in `_ready()` via `probe.ping.connect(_on_ping)` etc.
- `Probe.Process` emits each signal once, then quits.

## Result

✅ **PASS.** All three signals fire to both Go and GDScript listeners with correct args.


## Findings

### 1. ✅ Signal declaration as struct field works across arities

`Void`, `Solo[int]`, `Pair[string, Vector2.XY]` all registered, all callable from GDScript, all marshal types correctly. The doc's "verified fact #8" stands; no GDScript-side declaration boilerplate needed.

### 2. ✅ PascalCase → snake_case is applied to signal names too

`Ping`/`Damaged`/`Moved` → `ping`/`damaged`/`moved`. `has_signal("Ping") = false`. Consistent with methods (POC #3) and fields (POC #4).

### 3. ✅ One `Emit` dispatches to BOTH sides

A single `p.Damaged.Emit(7)` call fires the Go handler attached via `signal.Call(fn)` AND the GDScript handler attached via `signal.connect(callable)`. No bridge code needed. Go-side handlers always fired first in the observed order (likely because `Probe.Ready` connects before `Listener._ready`), but ordering shouldn't be relied on.

### 4. ✅ Type marshaling through signals matches POC #3

`Vector2.XY{X:3, Y:4}` passed through `Pair[string, Vector2.XY].Emit` arrives in GDScript as `Vector2(3.0, 4.0)`. Multi-value emit (string + Vector2) round-trips both at once.

### 5. ⚠️ Upstream API gap: `Signal.Void` has no `.Call(fn)`

`Signal.Solo`, `Signal.Pair`, `Signal.Trio`, `Signal.Quad`, `Signal.Quin`, `Signal.Hexa` all have a typed `.Call(fn)` method for Go-side connection. **`Signal.Void` does not** — only `.Emit()`. To Go-connect a Void signal, you have to reach into the underlying `Any`:

```go
p.Ping.Any.Attach(Callable.New(func() { ... }))
```

This is a real ergonomics regression for the zero-arg case — exactly the case beginners hit first. It also leaks the implementation detail that `Void` is `struct{ Any }`.

**Action for Phase 1:** gogogd's `signal.Connect(owner, fn)` (DESIGN_PRINCIPLES rule 2) must work uniformly across arities and paper over this gap. Inside the helper, a type switch on the signal value resolves the right `.Call`/`.Attach` path:

```go
// Sketch — Phase 1 implementation.
func Connect[S any](owner Node.Instance, sig *S, fn any) {
    switch s := any(sig).(type) {
    case *Signal.Void:
        s.Any.Attach(Callable.New(fn))
    case *Signal.Solo[int]:    // ... etc. via codegen, OR
    default:
        // Reflect: find .Call method on *S, call with fn.
    }
    // ...register owner-bound auto-disconnect on ExitTree.
}
```

The codegen variant is cleaner (one switch arm per supported signal arity); the reflection variant works for any user-defined signal type but is slower per-connect. Recommend codegen, since signals connect once and emit many times.

### 6. ✅ Signals as struct fields don't need initialisation

Bare-zero `Signal.Void` works. No `New*` constructor needed for the signal field itself — the registration machinery sets it up. This matches how a `chan` works in plain Go.

### 7. Open question (deferred): owner-bound auto-disconnect

DESIGN_PRINCIPLES rule 2 says `signal.Connect(owner, fn)` should auto-disconnect when `owner.ExitTree()` fires. This POC doesn't exercise that — both signal connections persist for the life of the Probe (which is the scene root) and the Listener (which lives until quit). POC #7 is the right spike for the auto-disconnect behavior.

## What this means for the plan

| Plan item | Action |
|---|---|
| Phase 1 `gogogd.Signal0/Signal/Signal2/...` aliases | Re-export the upstream `Signal.Void/Solo/Pair/...` under shorter names |
| `gogogd.Connect(owner, sig, fn)` helper | **Required to paper over the Void/.Call gap.** Codegen-or-typeswitch over supported arities. Lands in Phase 1C |
| GDScript-facing docs | Show every signal example side-by-side with the snake_case name a GDScript user will reference |
| `gogogd register` codegen | No special handling needed for signals — they're regular struct fields. Confirmed |
| §10 in ARCHITECTURE.md | Add a note about the upstream Void gap and explain why `gogogd.Connect` exists as a uniform helper |
