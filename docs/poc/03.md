# POC #3 — GDScript ↔ Go Method Calls + Marshaling

**Status:** PASS
**Date:** 2026-05-21
**Graphics.GD version:** `v0.0.0-20260521203745-bcb92de10087`
**Godot version:** `4.6.2.stable.official.71f334935`

## Hypothesis

ARCHITECTURE.md verified facts #4 and §10:
- Exported (capitalized) methods on a registered class are GDScript-callable, automatically.
- Names auto-convert PascalCase → snake_case.
- Standard scalar/math/container types marshal across the boundary without ceremony.
- Some name prefixes are reserved (`As`, plus `Super`/`UnsafePointer`/`Virtual`/`OnRegister`) and skipped (per `register_methods.go:33,45`).

## Findings

### 1. ✅ PascalCase → snake_case is automatic and total

`AddInts` is exposed *only* as `add_ints`. `has_method("AddInts") == false`. The Go-side identifier is invisible from GDScript. Same for fields: `TouchCount` is readable as `touch_count`; `probe.TouchCount` throws a script error.

This means **the gogogd authoring surface and the GDScript-facing surface are different names for the same method**. The Go code uses PascalCase, GDScript users see snake_case. Documentation must show both side-by-side for any GDScript-callable API.

### 2. ✅ `As`-prefixed methods are silently skipped

`AsHidden` returns `100` if called from Go, but `has_method("as_hidden") == false` from GDScript. The skip list (`register_methods.go:33`):

| Prefix/name | Skipped |
|---|---|
| `As*` | yes |
| `Super` | yes |
| `UnsafePointer` | yes |
| `Virtual` | yes |
| `OnRegister` | yes |

Phase 1 should document these as **reserved**: gogogd user code that names a method `AsFoo` will silently lose GDScript visibility. The `gogogd inspect <type>` CLI (Phase 2) should warn about reserved-prefix methods.

### 3. ✅ Type marshaling Just Works for the common cases

Verified round-trips:

| Go type | GDScript type | Round-trip |
|---|---|---|
| `int` | int | ✅ `add_ints(3, 4) = 7` |
| `string` | String | ✅ `greet("world") = "hello, world"` |
| `Vector2.XY` | Vector2 | ✅ `scale_vec((2,3), 1.5) = (3.0, 4.5)` |
| `Float.X` (`float32`) | float | ✅ |
| `[]int` | Array | ✅ `sum_slice([10,20,30]) = 60` |
| `bool` | bool | ✅ `toggle(true) = false` |
| void | void | ✅ |

Not tested in this POC (deferred to later spikes if needed): `Dictionary`, `Color`, `Vector3`, `[]string` / typed arrays, struct return, Node references. The pattern from `register_methods.go:60` (`propertyOf(...)`) suggests anything Godot's variant system supports works; anything else panics at registration time.

### 4. ✅ Exported fields auto-expose as properties

`TouchCount int` on Probe is readable from GDScript as `probe.touch_count`. The value updated correctly as methods incremented it (6 calls → 6). This validates verified fact #3 (exported fields are inspector properties / snake_case-converted accessors).

### 5. ✅ Lifecycle order across Go ↔ GDScript siblings

Observed order:
1. Go `Probe.Ready` (Go-side scene root child enters tree first)
2. GDScript `Caller._ready` (sibling, runs after the Go side is fully initialised)
3. Go `Probe.Process` (next frame)

No special sequencing required — the engine resolves the order. This means GDScript code can safely fetch a Go-backed sibling in `_ready` and call methods on it immediately.

## What this means for the plan

| Plan item | Action |
|---|---|
| Phase 1 wrapper-type exported methods | Confirmed safe: any `func (p *MyClass) Foo(args)` shows up as `foo` in GDScript automatically |
| Reserved prefixes | Document `As*`, `Super`, `UnsafePointer`, `Virtual`, `OnRegister` as reserved. `gogogd inspect` warns on collisions |
| User-facing docs | Show every GDScript-callable example with BOTH Go and GDScript names (e.g. "`func (p *Player) TakeDamage(n int)` — callable from GDScript as `take_damage(n)`") |
| `gogogd.Tunable[T]` etc. | Any cross-language API must use snake_case-safe Go names — no `AsFoo`, no `Virtual`-prefix |
| `Float.X` aliasing | Confirmed as Graphics.GD's preferred float type. gogogd's `gogogd.Delta = float32` (or alias to `Float.X`) is the right call. Document |
