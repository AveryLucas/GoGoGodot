# POC #6 — Reference Invalidation Stress (R10)

**Status:** PASS (with one ARCHITECTURE.md correction and one DESIGN_PRINCIPLES revision)
**Date:** 2026-05-21
**Graphics.GD version:** `v0.0.0-20260521203745-bcb92de10087`
**Godot version:** `4.6.2.stable.official.71f334935`
**Risk addressed:** R10 (high — was the biggest open question pre-Phase-1)

## Hypothesis

ARCHITECTURE.md verified fact #7 + DESIGN_PRINCIPLES rule 3:

> Godot references are invalidated when "no longer stored inside an `Extension[T]` struct and remain unused for two or more frames."
> Godot handles live on `Extension[T]` structs or in package-level `Preload` vars.

## Method

Reading Graphics.GD's `classdb/keepalive.go` revealed the mechanism precisely. Each registered class instance becomes a **root** (line 634: `roots.Insert(value, keepalive)`). Every frame, the keepalive walker recursively `Object.Use()`s every `Instance`-typed field reachable from those roots through structs, pointers, slices, maps, interfaces. Exported `Node` fields are skipped because they're owned by the scene tree.

With that model, the test is straightforward: spawn 5 orphan `Node` instances, hold references in 5 different shapes, and probe `Object.InstanceIsValid` every frame.

## Result

```
[POC6] frame=01  A.struct=true   B.slice=true   C.pkgvar=true   D.closure=true   E.manualUse=true
[POC6] frame=02  A.struct=true   B.slice=true   C.pkgvar=true   D.closure=true   E.manualUse=true
[POC6] frame=03  A.struct=true   B.slice=true   C.pkgvar=false  D.closure=false  E.manualUse=true
[POC6] frame=04  A.struct=true   B.slice=true   C.pkgvar=false  D.closure=false  E.manualUse=true
... (steady state through frame=13) ...
WARNING: ObjectDB instances leaked at exit
```

| Case | Storage | Surviving 12 frames? | Why |
|---|---|---|---|
| **A** | unexported `Node.Instance` field on `Extension[T]` | ✅ | walker pins it each frame |
| **B** | unexported `[]Node.Instance` slice on `Extension[T]` | ✅ | walker recurses into slices |
| **C** | package-level `var` | ❌ — invalid by frame 3 | **not** automatically pinned |
| **D** | closure capture (closure held on struct field) | ❌ — invalid by frame 3 | walker can't see func captures |
| **E** | unexported field + manual `Object.Use(handle)` per frame | ✅ | manual keepalive |

## Findings

### 1. ✅ Two-frame TTL is exact

Frames 1–2 show all handles valid; by frame 3, unpinned handles flip to invalid. Confirms verified fact #7 to the frame.

This means **any helper that holds a Godot handle across more than 2 frames must either:**
- be reachable from an `Extension[T]` root (Cases A/B), OR
- call `Object.Use()` on the handle every frame (Case E).

### 2. ⚠️ Package-level vars are NOT automatically pinned

DESIGN_PRINCIPLES rule 3 currently says:

> Godot handles live on `Extension[T]` structs or in package-level `Preload` vars.

The second clause is **wrong** given what `keepalive.go` actually does — there's no mechanism that registers package vars as roots. Case C confirms: a `var pkgHandle Node.Instance` set in `Ready()` is invalid by frame 3.

**Action — pick one, document it:**
- **Option A (preferred): drop the package-var promise.** Tighten rule 3 to "handles live on `Extension[T]` structs. Period." Force users into autoload-class fields for cross-scene shared state, which is more Godot-native anyway.
- **Option B: implement `gogogd.Pin(&pkgHandle)`** — registers the handle as a keepalive root, calls `Object.Use` per frame. More complex; one more concept to learn; the "package-level preload var" pattern is rarely the right shape in practice.

Recommend Option A. Autoloads (`autoload/` in the default template, DESIGN_PRINCIPLES rule 20) are how Godot already wants cross-scene state held. Package vars are a vestigial Go idiom that doesn't map to the engine.

### 3. ⚠️ Slices on `Extension[T]` ARE pinned (under-promised in the doc)

The doc says "Extension[T] struct" generically. POC #6 confirms the walker handles slices, arrays, pointers, maps, interfaces — anything reflect-visible. This is actually **better than the doc claims** and worth documenting because:

- Phase 2's `Pool[T]` can hold its bucket as `[]T` directly without per-element `Object.Use()` calls.
- Signal connection lists (`[]conn`) can hold receivers via owner-bound shells.
- Helpers can stash `map[string]Node.Instance` lookup tables on a component without per-frame keepalive work.

**Action:** ARCHITECTURE.md §11 should add a "what the walker reaches" subsection: any `Object`/`Node`/etc.-typed value reachable via struct field, slice, pointer, map, or interface from an `Extension[T]` root is automatically `Use()`'d per frame.

### 4. ❌ Closures capture references but the walker can't see them

Case D stashes a closure on a struct field. The closure captures a `Node.Instance` not stored anywhere visible to reflection. By frame 3, the captured handle is invalid even though the closure itself is still callable.

This has direct implications:

- **`After(owner, dt, fn)`** — the `fn` argument may close over Node handles. Those handles need an explicit-owner path, not a "trust the closure capture" path.
- **Signal `Connect(owner, fn)`** — same. The `owner` argument is what gives gogogd a reflect-visible field to pin handles through.
- **`Bus.On("name").Connect(owner, fn)`** — same.

In other words: **DESIGN_PRINCIPLES rule 1's "helpers take an owner as their first argument" is non-negotiable.** This POC is the concrete justification — without an owner, captured handles die in 2 frames.

### 5. ✅ Manual `Object.Use(handle)` works as the escape hatch

Case E proves that calling `Object.Use(handle)` in every `Process` keeps a handle alive indefinitely. This is the right path for:

- Long-lived autoloads that hold handles they don't want to expose as `Extension[T]` fields.
- Helpers that need to keep an internally-managed handle alive across frames without forcing it into the user's struct shape.

**Action:** Phase 1's `gogogd.Pin(handle)` (if we implement it) can be a thin wrapper around the manual-Use pattern. Decide alongside the rule-3 revision above.

### 6. Leaked-at-exit warning is expected, not a bug

Output ends with `WARNING: ObjectDB instances leaked at exit`. POC #6 created 5 orphan nodes and never `QueueFree`'d them — the warning just reports we left them dangling. Not a reference-invalidation issue. Phase 1 helpers that spawn nodes should track them and free on `ExitTree` to keep this clean.

## What this means for the plan

| Plan item | Action |
|---|---|
| DESIGN_PRINCIPLES rule 3 | Drop "or in package-level `Preload` vars." Tighten to: "Godot handles live on `Extension[T]` structs (any depth, any container type). Anywhere else and they invalidate after 2 frames of disuse." |
| ARCHITECTURE.md §11 / §12 | Add a subsection: "What the walker reaches — any handle field, slice element, map value, pointer target, or interface payload reachable from a registered class root is `Object.Use()`'d every frame." |
| Phase 1 helpers | `After(owner, dt, fn)`, `Every(owner, dt, fn)`, `Bus.On(...).Connect(owner, fn)`, `Sequence(owner, ...)` all take `owner` — and **internally stash any handle they need to keep alive as a field reachable from `owner`**, not in closure captures |
| Phase 1 `gogogd.Pin(handle)` | **Optional.** Only needed if the autoload pattern (DP rule 20) isn't enough. Defer decision until Phase 1 implementation reveals whether autoloads cover the use case |
| `gogogd doctor` lint | Flag any helper that takes a `fn` without an `owner` parameter as suspicious. (Phase 2 — once the helper inventory is known) |
| Educational docs | Add a "handles and lifetimes" page early in the tutorial ramp. Use Case D as the cautionary example: "this looks like it should work, but the closure capture isn't pinned" |
