# POC #2 — Child Wiring + `ggd:"strict"` Hook Point

**Status:** PASS (with two corrections to ARCHITECTURE.md)
**Date:** 2026-05-21
**Graphics.GD version:** `v0.0.0-20260521203745-bcb92de10087`
**Godot version:** `4.6.2.stable.official.71f334935`

## Hypothesis

1. Exported `Node`-typed fields on a registered class are auto-populated before `Ready()`.
2. `gd:"name"` controls the node Graphics.GD looks up under the parent (single name or multi-segment path).
3. If the target doesn't exist in the scene, Graphics.GD silently auto-creates it (verified fact #5).
4. There's an observable post-Ready signal to distinguish auto-created from scene-authored, so `ggd:"strict"` is implementable in user space.

## Result

✅ **All four confirmed.** Raw output:

```
[POC2] field=AutoBare  tag=""                 zero=false name="AutoBare"   owner_zero=true  owner_name=""
[POC2] field=Renamed   tag="CustomName"       zero=false name="Renamed"    owner_zero=true  owner_name=""
[POC2] field=Existing  tag=""                 zero=false name="Existing"   owner_zero=false owner_name="Probe"
[POC2] field=Nested    tag="Container/Leaf"   zero=false name="Leaf"       owner_zero=false owner_name="Probe"
[POC2] field=Skipped   tag="-"                zero=true
```

## Findings

### 1. `Owner() == zero` is the strict-mode signal ✅

Scene-authored children have `Owner() == <scene root>` (here, `Probe`). Auto-created children have `Owner() == zero`. This is exactly the lever `ggd:"strict"` needs:

```go
// Inside gogogd's post-Ready strict check:
for _, f := range strictFields(self) {
    child := getNodeField(self, f)
    if child.Owner() == (Node.Instance{}) {
        panic(fmt.Sprintf("strict: %s.%s was auto-created (no matching scene node)",
            self.Type(), f.Name))
    }
}
```

**This makes `ggd:"strict"` cheap to implement — no Graphics.GD fork, no pre-wiring hook, no proxy.** It's a single reflection pass that the user (or gogogd) calls at the top of `Ready()`. Phase 1 ships this as `gogogd.AssertStrict(self)` and the wrapper-type `Ready()` autocalls it.

### 2. ⚠️ `gd:"Tag"` is lookup-only, not rename-on-create

When `Renamed gd:"CustomName"` doesn't match a scene node, Graphics.GD creates a child named `"Renamed"` (the field name), **not** `"CustomName"` (the tag). The tag is only consulted to *look up* an existing node (`register_class.go:1064-1070`); on auto-create, the field name wins (line 1089: `SetName(field.Name)`).

This contradicts the natural reading of ARCHITECTURE.md §8 (`gd:"Ui/HealthBar"` "populates the field from the scene"). The behavior IS correct for the *match-an-existing-node* case (and the doc's examples assume that case). But:

- A user who tags an auto-created field thinking the tag will rename it will be surprised.
- The footgun gets worse with multi-segment tags: `gd:"Container/Leaf"` on a no-existing-node case creates a flat child named after the field, completely ignoring the intended hierarchy.

**Action:** Document this clearly in DESIGN_PRINCIPLES.md and the §8 explainer. Consider making `ggd:"strict"` the default for any tagged field — if you bothered to tag it with a path, you probably wanted the path to exist.

### 3. ✅ Multi-segment paths work for lookup

`gd:"Container/Leaf"` correctly wires to a scene-authored `Leaf` two levels deep. Multi-segment paths are honored by `Path.ToNode` and `Node.HasNode`. Validates the doc's example syntax.

### 4. ✅ `gd:"-"` opts out cleanly

A `gd:"-"` field is not touched. Field stays zero — neither auto-created nor wired. Confirms the "skip me" escape hatch.

### 5. ✅ Wiring happens before `Ready()`

By the time `Ready()` runs, all children are resolved. No need to defer logic to a later frame. The strict check naturally sits at the top of `Ready()`.

## What this means for the plan

| Plan item | Action |
|---|---|
| `ggd:"strict"` impl | Trivial: `gogogd.AssertStrict(self)` does a reflection pass and panics on any strict field with `Owner() == zero`. Lands in Phase 1 (bind layer, ~30 LOC) |
| ARCHITECTURE.md §8 | Clarify: `gd:"name"` is lookup-only. On auto-create, field name wins. Add a footgun callout |
| `ggd:"strict"` as default? | Open question. Strong case: any explicitly-tagged field probably means "I expect this exact scene node." Conservative default would auto-strict tagged fields and require `ggd:"loose"` to opt out. Decide before Phase 1 freezes the tag grammar |
| DESIGN_PRINCIPLES rule 16 | Currently says "missing child auto-created unless `ggd:"strict"` is added." Add the *behavior* note: auto-create uses the field name, not the tag value |
| Wrapper types | `NodeExt[T].Ready()` shim should optionally call `AssertStrict(self)` first. Simple addition to the inheritance ladder in Phase 1B |
