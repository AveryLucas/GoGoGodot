# gogogd examples

Each example is a self-contained Go + Godot project demonstrating
gogogd's authoring surface. All three build and run headless under
`gogogd test`.

| # | Example | What it shows |
|---|---|---|
| 01 | [`01-coin-collector`](01-coin-collector/) | The smallest "real game" shape. Player auto-paths toward coins, area-overlap detection, custom `signals.Signal0`, owner-bound `signals.Connect0`, `tree.Children[T]`, `scenetree.Quit`. ~150 lines. |
| 02 | [`02-shooter`](02-shooter/) | Bullets with `timing.After` self-cleanup, enemy spawner via `spawn.Add`, `timing.Cooldown` on the fire button, `tree.OnlyIf` body-overlap. |
| 03 | [`03-menus-and-save`](03-menus-and-save/) | Vertical slice covering typed `settings.For[T]`, versioned `save` slots, modal `ui.Push`/`ui.Pop`/`ui.SetFocus` stack, global `bus.On(name).Connect`, `i18n.Tr`, and `fsm` for game-state. Subpackaged across `game/`, `prefs/`, `saves/`, `screens/`. |

## Running an example

Each example is its own Go module. From the example's directory:

```sh
go mod tidy
gogogd test --duration 5s   # headless smoke test
# or
gogogd run                  # full interactive launch
```

The first run does a one-time `.godot/` cache bootstrap. Subsequent
runs are just code-rebuild + Godot relaunch.

## Conventions

- `main.go` is a one-liner: `startup.Scene()`. Class registration is
  in the codegen-emitted `gogogd_register.go` (regenerated by `gogogd
  register`, which `gogogd run`/`gogogd build`/`gogogd test` run
  automatically).
- One Go file per component type when the component has its own
  logic (`player.go`, `coin.go`, `hud.go`). Tiny components can share
  a file.
- Scene files (`.tscn`) live in `graphics/`. They're plain text;
  commit them.

## Reading order

New to gogogd? Start with [`01-coin-collector`](01-coin-collector/) —
it introduces the embed shape, lifecycle methods, child wiring, custom
signals, owner-bound connections, scene-tree traversal, and clean
shutdown in ~150 lines. Then [`02-shooter`](02-shooter/) for
spawn/cleanup patterns, and [`03-menus-and-save`](03-menus-and-save/)
for the production-systems surface (save, settings, modal UI, i18n).
